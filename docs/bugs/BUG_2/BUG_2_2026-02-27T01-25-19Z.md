# BUG_2 Instance - 2026-02-27T01-25-19Z

## Description
- iOS ride-along monitor displayed no usable mic activity and never auto-started sessions, so no turns were persisted.

## Symptoms Observed
- Session stayed in "Idle (waiting for speech)".
- Audio level diagnostics remained near zero.
- No `rideAlongSessionBegin` event fired, so no session start or turn persistence occurred.

## Troubleshooting Steps
1. Verified plugin registration path and iOS compilation status.
   - Result: Plugin was now loading and compiling successfully.
2. Reviewed ride-along auto-start flow in `RideAlongsTab`.
   - Result: Session start depends on speech detection from `AudioRecording.getLevels()` before any session exists.
3. Reviewed iOS `getLevels()` implementation.
   - Result: It returned `0` unless `AVAudioRecorder` was already recording, creating a circular dependency.
4. Implemented ambient mic level fallback in iOS plugin.
   - Result: `getLevels()` now uses an `AVAudioEngine` monitor before sessions begin.
5. Stopped ambient monitor when session startup begins to avoid competing taps.
   - Result: Existing ride-along recording/stream flow remains exclusive.
6. Rebuilt and synced iOS project.
   - Result: Native build and sync succeeded.

## Resolution Summary
- Root cause was pre-session speech detection relying on a level source that only exists during active recording.
- Added ambient level monitoring for iOS:
  - `resolveAmbientLevel(_:)`
  - `ensureLevelMonitor()`
  - `stopLevelMonitor()`
- Updated `getLevels()` to use ambient fallback when no active recorder exists.

## Lessons Learned
- Any auto-start logic based on pre-session speech levels needs a non-recording level source on each platform.
- Web and iOS level acquisition paths must stay behaviorally aligned to keep monitor UX consistent.
