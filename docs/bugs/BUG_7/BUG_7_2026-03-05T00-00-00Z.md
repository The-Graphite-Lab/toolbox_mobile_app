# BUG_7 Troubleshooting Log - 2026-03-05T00:00:00Z

## Description
Bottom navigation was not guaranteed to remain visible because the root app shell could grow taller than the viewport. Nav action icons were also not evenly distributed because one action used a different width strategy.

## Symptoms
- On some screens/content states, the bottom nav could be pushed off-screen.
- Home/Coaching/Logout icons were not uniformly spaced.

## Troubleshooting Steps
1. Checked existing bug ledger (`BUG_1` to `BUG_6`) and found no dedicated nav anchoring/even-distribution entry.
2. Reviewed app shell and nav styles in `app/page.tsx`.
3. Identified two causes:
   - Root shell used `minHeight` without hard viewport constraint, allowing page-level overflow.
   - Logout action used a separate style path from tab actions, breaking equal distribution.
4. Applied fix:
   - Constrained shell to `height: 100dvh` with `overflow: hidden`.
   - Kept content in a flex child with `overflow: hidden` while tab panels handle internal `overflowY: auto`.
   - Used one equal-flex button style for all three nav actions.

## Solution Summary
The nav now stays visible at the bottom because the app shell is viewport-locked and scrolling is isolated to panel content. All three nav actions are evenly distributed via shared equal-flex button styling.

## Lessons Learned
- For persistent bottom controls, lock the shell height to viewport and keep scroll behavior inside content panes.
- Use one shared action style for primary nav items to keep spacing consistent.
