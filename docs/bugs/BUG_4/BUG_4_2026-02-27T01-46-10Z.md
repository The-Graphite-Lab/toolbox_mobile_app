# BUG_4 Instance - 2026-02-27T01-46-10Z

## Description
- Ride-along backend writes were still failing after auth-token propagation because iOS native was directly posting to backend routes that are IAM-signed in this environment.

## Symptoms Observed
- 403 responses on iOS native requests with Authorization parse errors.
- Session did not persist to backend.
- Turns were not logged.
- Upload warnings surfaced while stop flow completed locally.

## Troubleshooting Steps
1. Traced iOS plugin websocket message handling.
   - Result: On iOS, finalized `Begin`/`Turn` payloads were routed to native backend POST helpers, not JS listener events.
2. Compared web vs iOS behavior.
   - Result: Web emits `rideAlongSessionBegin` and `rideAlongTurn` events, then JS Amplify APIs persist data.
3. Confirmed API Gateway error pattern.
   - Result: Native `Authorization` header path was incompatible with API Gateway IAM signing expectations for those routes.
4. Refactored iOS plugin flow:
   - Removed native ride-along backend POST/upload/finish helpers.
   - Added event emission on iOS for:
     - `rideAlongSessionBegin`
     - `rideAlongTurn`
     - `rideAlongSessionStopped`
   - Kept native responsibilities to recording + websocket only.
5. Added stop payload support for JS upload path:
   - `stopRideAlongSession` now includes optional `base64Data`.
   - JS stop flow can build a blob from base64 for upload when `filePath` is not web-fetchable.
6. Verified builds:
   - Next build passes.
   - iOS simulator build passes.

## Resolution Summary
- Root cause was platform divergence: iOS native plugin persisted directly to backend while web used Amplify JS persistence.
- Standardized persistence path to JS Amplify for both platforms by emitting iOS plugin events.
- This avoids IAM signature/header mismatch from native URLSession calls.

## Lessons Learned
- Keep backend persistence in one trusted path (Amplify JS) unless native signing requirements are fully implemented.
- Capacitor plugin should emit domain events and let app-layer networking handle auth/persistence consistency.
