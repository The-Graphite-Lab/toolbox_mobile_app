# BUG_6 Troubleshooting Log - 2026-03-05T00:00:00Z

## Description
On wide/landscape screens, the app background art did not fill the viewport. The shell background was height-locked (`auto 100vh`) and left uncovered horizontal space.

## Symptoms
- Background art appeared clipped or undersized when viewport width exceeded viewport height.
- Behavior reproduced in full-screen wrappers (`app/page.tsx`, auth shell, and loading screen).

## Troubleshooting Steps
1. Checked existing bug ledger for similar rendering/layout bugs (`BUG_1` to `BUG_5`); no direct match.
2. Reviewed full-screen wrapper styles and found repeated pattern:
   - `width: 100vw`
   - `height: 100vh`
   - `backgroundSize: auto 100vh`
3. Updated wrappers to viewport-safe fill strategy:
   - Use `minHeight: 100dvh` (or `height: 100dvh` for fixed overlay)
   - Use `width: 100%`
   - Use `backgroundSize: cover`

## Solution Summary
Replaced height-locked background sizing with viewport-fill sizing and `cover` scaling in all full-screen shells, ensuring the background fills both portrait and landscape viewports.

## Lessons Learned
- Avoid `backgroundSize: auto 100vh` for full-screen decorative backgrounds when landscape support is required.
- Prefer a consistent shared full-screen style strategy across app root, auth shell, and loading overlay.
