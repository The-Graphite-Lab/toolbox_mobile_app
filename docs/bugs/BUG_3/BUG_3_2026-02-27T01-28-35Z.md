# BUG_3 Instance - 2026-02-27T01-28-35Z

## Description
- Ride-along requests to the `connections` backend failed in app runtime due CORS, so session/token/turn APIs did not execute.

## Symptoms Observed
- Browser/WebView reports CORS errors before backend route logic runs.
- Ride-along flows fail at API calls (`/ridealongs/assembly/token` and related session endpoints).

## Troubleshooting Steps
1. Reviewed existing CORS middleware in `connections/src/app.js`.
   - Result: only set `Access-Control-Allow-Origin` and wildcard headers.
   - Missing: explicit method allowance and preflight short-circuit.
2. Verified no explicit `OPTIONS` handling existed.
   - Result: preflight could fail/block prior to functional route handling.
3. Implemented robust CORS middleware:
   - Added `Access-Control-Allow-Methods`.
   - Added dynamic `Access-Control-Allow-Headers` echo from request preflight headers.
   - Added `Access-Control-Max-Age`.
   - Added `OPTIONS` 204 immediate response.

## Resolution Summary
- Root cause was incomplete CORS handling for preflight requests in the Lambda Express app.
- Fix now supports browser/WebView preflight and standard auth/custom headers for ride-along APIs.

## Lessons Learned
- For Amplify REST + browser/WebView callers, CORS middleware must include full preflight handling, not just origin/header defaults.
- Echoing `access-control-request-headers` is the safest way to avoid missing required auth headers in preflight.
