# BUG_5: WebSocket receive error when ride-along session ends

## Description
When a ride-along session ended (user completed or server sent Termination), the app showed: "WebSocket receive error: The operation couldn't be completed. Socket is not connected."

## Symptoms
- Session connected, created, and did turns successfully.
- When the session ended, a red error banner appeared with the WebSocket message.
- UI could show "LIVE" / "Monitoring" while also "No active session" and the error.

## Root cause
The iOS native plugin runs a receive loop on the AssemblyAI WebSocket. When the session ends, either we call `stopRideAlongWebSocket()` (cancel) or the server closes the connection. The in-flight `receive` then completes with a failure (e.g. "Socket is not connected"). The code treated all receive failures as user-facing errors.

## Solution
Treat receive failures that indicate an expected close (cancelled, socket not connected, connection closed) as normal shutdown. Only emit `rideAlongSessionError` for unexpected errors. In `AudioRecording.swift`, added `isExpectedWebSocketCloseError` and in the receive `.failure` branch only call `emitRideAlongSessionError` when the error is not expected.

## Lessons
- WebSocket receive can fail when the other side closes or we cancel; that is not necessarily an error to show the user.
- Differentiate "connection closed during normal shutdown" from "unexpected network/stream error."
